# Migration Guide: v2.x to v3.0.0

> **Draft.** 3.0 is not released. This lists what the release will change so
> the breaking pull requests and this guide land together. Items marked
> *(planned)* are not on `main` yet.

The theme of 3.0 is small: **your CSS starts doing what it says.** Most 2.x
applications already carry a stylesheet that reaches only the root widget.
3.0 makes it reach every widget, and removes a handful of APIs that were
deprecated long ago.

## 1. CSS reaches every widget by default *(planned)*

`dom_from_render` and `css_layout` become the default.

| | 2.x default | 3.0 default |
|---|---|---|
| [`AppBuilder::dom_from_render`] | off | **on** |
| [`AppBuilder::css_layout`] | off | **on** |

**What changes on screen.** Only what your stylesheet already asks for. Before
3.0, a rule like `.title { text-align: center; }` matched nothing below the
root, so it was silently ignored. In 3.0 it applies. Every shipped example was
compared cell by cell with both settings: none broke, and the ones that changed
were the ones whose own CSS started to apply.

Review your stylesheet for rules you wrote but never saw take effect.

**Keeping 2.x behavior.** Turn them back off:

```rust
let app = App::builder()
    .dom_from_render(false)
    .css_layout(false)
    .build();
```

### A `background` fills its box

With `dom_from_render`, a node's CSS `background` now fills its whole box, not
only the cells its widget happens to write. A widget's own background - from a
builder such as `.bg(...)` - still wins over the stylesheet, and a child's own
background still wins inside the child.

## 2. A stack sizes its children to their content *(planned)*

In 2.x a child added with `.child(...)` gets an equal share of the stack's
space, so

```rust
vstack()
    .child(Text::new("Title"))
    .child(Text::new("Subtitle"))
```

puts "Subtitle" halfway down the screen. In 3.0 [`Stack::content_sized`] is
on by default: a child that can measure itself (`Text`, `Border`, a nested
`Stack`, ...) takes the size of its content, and only the children that fill
share what is left. `child_sized` and `child_flex` still win. Under
`css_layout`, a child's CSS box along the stack - `height`/`width`,
`min-*`/`max-*`, margins - counts toward that size, so `margin-top: 2` moves
a line of text down instead of hiding it, and a `display: none` child takes
no space.

**What changes on screen.** Unsized text and bordered boxes pack together
instead of spreading out. Layouts that relied on the spread - a header, a
body that fills, a footer - keep working when the body is a widget that fills
(a list, a table, a scroll view); if the body is itself content-sized, give it
`child_flex(1.0)` so it takes the rest.

**Keeping 2.x behavior** per stack:

```rust
vstack().content_sized(false)
```

Widgets answer through the new `View::measure`, added in 2.x. A custom widget
that does not implement it keeps filling whatever it is given.

## 3. A color you name outranks the stylesheet - everywhere *(planned)*

2.x established the order **builder > stylesheet > widget default**, but four
public fields could not tell "you named this color" from "this is the default",
so a named color lost to the stylesheet. They become `Option<Color>`:

| Type | Field |
|---|---|
| `DiagramColors` | `node_fg` |
| `ProcColors` | `name` |
| `Slide` | `content_color` |
| `DateTimePicker` | `field_fg` |

If you set these through builders, nothing changes. If you construct the
struct or assign the field directly, wrap the value:

```rust
// 2.x
colors.node_fg = Color::WHITE;
// 3.0
colors.node_fg = Some(Color::WHITE);
```

`None` means "let the stylesheet decide, then the widget default".

## 4. Removed deprecated APIs

| Removed | Deprecated since | Use instead |
|---|---|---|
| `devtools::enable_devtools()` | 2.1.0 | `App::enable_devtools()` |
| `devtools::disable_devtools()` | 2.1.0 | `App::disable_devtools()` |
| `devtools::is_devtools_enabled()` | 2.1.0 | `App::is_devtools_enabled()` |
| `devtools::toggle_devtools()` | 2.1.0 | `App::toggle_devtools()` |
| `RenderContext::child_ctx_with_overflow` | 2.76.0 | `RenderContext::render_child_with_overflow` |

`child_ctx_with_overflow` clipped a child to its own area, which never clips
anything. `render_child_with_overflow` clips to the container's box and also
registers the child in the DOM, so CSS reaches it.

## Not in 3.0

- **Widget event dispatch** (`on_key(&self, &mut NodeCtx)`). There is no
  runtime dispatch to widgets to migrate *from* yet; `Interactive::handle_key`
  stays. Planned for 3.x.
- **Layout engine as the authority for placement.** Containers keep computing
  their own geometry; CSS adjusts the box (`width`, `height`, `margin`,
  `display: none`, `min-*`/`max-*`) and `gap`. Planned for 3.x.
